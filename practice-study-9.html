    Quiz 9 study guide: Database Concepts

    The core Chapter 10 ideas in one place, using the Lab 6 Research Papers database as the example. Read this, then try the practice set. Your course notes are still the official source.

    Building blocks

    TermMeaning
    DatabaseA collection of related tables about people, places, or things
    DBMSSoftware to create, manage, and query databases, like Access
    TableRelated records about one subject
    RecordOne row: everything about one item
    FieldOne column: a single piece of data

    Hierarchy: database, then table, then record, then field. Data is split into related tables so each fact is stored once, which cuts down on duplication and inconsistencies.

    Primary keys and foreign keys

    Primary keyForeign key
    JobUniquely identifies each recordLinks a child record to its parent
    Can repeat?NeverYes, that’s what makes one-to-many work
    Can be empty?NeverCan be null
    NameAnyDoesn’t have to match the primary key’s name
    Data typeAnyMust match the primary key’s data type and hold the same kind of information
    Lab 6 exampleClient.ClientID, PaymentMethod.MethodIDCharges.ClientID, Payments.ClientID, Payments.PaymentType

    A primary key can be more than one field (a composite key). Access indexes it automatically as “Yes (No Duplicates).” Charges and Payments have no primary key in Lab 6 because ClientID repeats there.

    Relationships

    The table with the primary key is the parent; the table with the foreign key is the child. Lab 6 has three one-to-many relationships:

    Parent (1)Child (∞)Linked on
    ClientChargesClientID → ClientID
    ClientPaymentsClientID → ClientID
    PaymentMethodPaymentsMethodID → PaymentType

    Referential integrity and cascades

    Referential integrity means every child must have a parent, so there are no orphans.

    You do thisRI on, cascade offRI on, cascade on
    Add a child with a nonexistent parent IDBlockedBlocked
    Delete a parent that has childrenBlockedParent and all its children deleted (Cascade Delete)
    Change a parent’s primary keyBlockedChildren’s foreign keys update (Cascade Update)
    Delete one child recordOnly that child is deletedOnly that child is deleted
    One direction only. Cascades flow from parent to child. Deleting or changing a child never affects the parent.

    Access objects

    ObjectUsed for

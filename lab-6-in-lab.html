    CSE 2111 In-Lab 6, step by step

    Same routine as the Pre-Lab: build six tables, link them, then import six text files. The “how to click it” screenshots are borrowed from your Pre-Lab instructions, so the table names in them won’t match. The finished-table screenshots at the end are from the In-Lab itself. Tap any screenshot to enlarge it and tick steps as you go.

    1

    Build the six tables

    Create → Table Design for each one.

    Big difference from the Pre-Lab: this lab uses spaces. Table names like Event Type and field names like First Name have a space in them. Type them exactly as shown, spaces included.

    1. Open CSE 2111 In Lab 6 Events Master.accdb from your SimNet download and close the pink security bar. If you want it in your Lab 6 folder, do File → Save As → diskette button, like the Pre-Lab.

    2. The routine for every table: Create → Table Design, type the field names, set the Data Type, set Field Size in the bottom pane, click the first field and hit Primary Key, then save with the table name.

    3. Event Type

      FieldTypeSize / extra
      TypeIDShort Text10, primary key
      Type DescriptionShort Text150

    4. Location

      FieldTypeSize / extra
      LocationIDShort Text10, primary key
      Location NameShort Text175

    5. Organizer

      FieldTypeSize / extra
      OrganizerIDShort Text10, primary key
      First NameShort Text50
      Last NameShort Text100

      The PDF says “1 100” for Last Name. That’s a typo; use 100.

    6. Workers Info

      FieldTypeSize / extra
      WorkerIDShort Text10, primary key
      First NameShort Text50
      Last NameShort Text100
      AddressShort Text150
      CityShort Text25
      StateShort Text2, Default Value "OH"
      ZipcodeShort Text5

      Note it’s Zipcode with a lowercase c this time. No input masks in this lab.

    7. Scheduled Events

      FieldTypeSize / extra
      EventIDShort Text10, primary key
      OrganizerIDShort Text10
      LocationIDShort Text10
      TypeIDShort Text10

    8. Worker Assignments

      FieldTypeSize / extra
      AssignIDShort Text10, primary key
      WorkerIDShort Text10
      EventIDShort Text10

      The PDF says “1 10” for EventID. Also a typo; use 10.

    Every table gets a primary key here, unlike Charges and Payments in the Pre-Lab. If Access asks “create a primary key now?”, you forgot to set one. Click Cancel and set it yourself.
    2

    Relationships

    Five links. Scheduled Events is the hub.

    1. Close every table, then go to Database Tools → Relationships.

    2. Click Add Tables (or Show Table) and double-click all six tables, then close the list. You should see six boxes.

    3. Drag the boxes into a layout you can read. Something like this keeps the lines from crossing:

      Event Type ─┐
Location  ──┼──► Scheduled Events ──► Worker Assignments ◄── Workers Info
Organizer ──┘

    4. Make each link by dragging (press, hold, move, release) the field from the first table onto the matching field in the second. Always drag from the table where the field is the primary key.

      #Drag fromOnto
      1Event Type → TypeIDScheduled Events → TypeID
      2Location → LocationIDScheduled Events → LocationID
      3Organizer → OrganizerIDScheduled Events → OrganizerID
      4Scheduled Events → EventIDWorker Assignments → EventID
      5Workers Info → WorkerIDWorker Assignments → WorkerID

      Dragging not cooperating? Click Edit Relationships → Create New… and pick the tables and fields from the dropdowns.

    5. In each Edit Relationships box, tick Enforce Referential Integrity (and both cascade boxes, like the Pre-Lab), make sure it says One-To-Many, then click Create.

    6. Check that all five lines show a 1 on the parent side and ∞ on the other. Then click Close and Yes to save.

    Says “One-To-One” or “Indeterminate”? You dragged the wrong direction or a primary key isn’t set. Cancel, check the key icons, and drag again from the table where that field is the key.
    3

    Import the text files

    Same wizard as Pre-Lab Part 3, six times.

    1. Close all tables. Go to External Data → New Data Source → From File → Text File.

    2. Browse to the file, choose Append a copy of the records to the table, pick the matching table from the dropdown, and click OK.

    3. Leave Delimited selected, click Next.

    4. Choose Comma, Text Qualifier ", leave First Row Contains Field Names unchecked, click Finish. Don’t save the import steps.

    5. Do all six in this exact order (parents before the tables that point to them):

      OrderFileAppend toRows
      aEvent_Type.txtEvent Type6
      bLocation.txtLocation6
      cOrganizer.txtOrganizer6
      dWorkers_Info.txtWorkers Info16
      eScheduled_Events.txtScheduled Events12
      fWorker_Assignments.txtWorker Assignments21
    Heads up on Location.txt: the apostrophe in “Skully’s Music-Diner” is a special curly character. If it shows up as a weird symbol after importing, either fix it by hand in the table, or redo that import and in the wizard click Advanced… and set Code Page to Western European (Windows).

    Check your work against the lab’s screenshots

    1. Open each table and compare. The little + signs on the left just mean the table has related records; that’s a good sign your relationships worked.

      The typos in worker data (“Cicinnati”, “Tacom”, “Matther”) are in the original file. Leave them.

    2. Close all tables, save, and upload CSE 2111 In Lab 6 Events Master.accdb to SimNet.

    Import error or missing rows? Usually a field name that doesn’t match exactly (watch the spaces), fields in the wrong order, or a file imported before its parent table.

    Research Papers database

    Build 4 tables, link them, then fill them from Excel.

    Open and save your copy

    1. Open Research Papers Master.accdb. If a pink security bar appears, close it with the × on the right.

    2. Click File → Save As, then click the diskette Save As button at the bottom. Don't pick any of the options above it.

    3. Save it into your Lab 6 folder.

    Table 1: Client

    1. Go to Create → Table Design.

    2. Click the Save icon in the top-left corner and name the table Client.

    3. Type ClientID as the first field name, then click the Primary Key button so a key appears beside it.

    4. With ClientID selected, set Field Size to 5 in the properties at the bottom.

    5. Add the rest of the fields. Spelling and capitalization must match exactly, with no spaces, or the Excel import breaks later.

      FieldTypeField Size / extra
      ClientIDShort Text5, primary key
      FirstNameShort Text25
      LastNameShort Text50
      AddressShort Text60
      CityShort Text25
      StateShort Text2, Default Value OH (next step)
      ZipCodeShort Text5
      HomePhoneShort Text10, Input Mask (step after next)

    6. Click the State field and set Default Value to "OH".

    7. Click HomePhone, click in Input Mask, then click the … button. Click Yes when Access asks to save.

    8. Pick Phone Number and click Finish.

    9. Close the Client table (just the tab, not Access) and save if asked.

    Table 2: Charges

    1. Go to Create → Table Design again and enter these fields. No primary key on this table.

      FieldTypeField Size / extra
      ClientIDShort Text5
      AmountCurrencynone
      ChargeDateDate/TimeInput Mask: Short Date

    2. Click ChargeDate, click in Input Mask, then …, then Yes to save.

    3. Name the table Charges and click OK. When Access asks to create a primary key, click No.

    4. Choose Short Date, then Finish.

    5. Close the table and click Yes to save.

    Tables 3 and 4: Payments and PaymentMethod

    1. Build Payments the same way. No primary key (click No when asked). Give PaymentDate a Short Date input mask.

      FieldTypeField Size / extra
      ClientIDShort Text5
      AmountCurrencynone
      PaymentDateDate/TimeInput Mask: Short Date
      PaymentTypeShort Text2

    2. Build PaymentMethod. MethodID is the primary key.

      FieldTypeField Size / extra
      MethodIDShort Text2, primary key
      MethodTypeShort Text20

    Relationships

    1. Close every table. Go to Database Tools → Relationships.

    2. Double-click each of the four tables to add it, then click Close.

    3. Drag the boxes into roughly this layout.

    4. Link 1: drag ClientID from Client onto ClientID in Charges.

    5. Tick all three boxes: Enforce Referential Integrity, Cascade Update Related Fields, Cascade Delete Related Records. Click Create. Do this for every link.

    6. Link 2: drag ClientID from Client onto ClientID in Payments. Tick all three boxes, then Create.

    7. Link 3: drag MethodID from PaymentMethod onto PaymentType in Payments. The field names differ here, and that's correct. Tick all three boxes, then Create.

    8. Click Close and Yes to save the layout. You should see 1 and ∞ symbols on each line.

    3. Choose From File → Excel.

    4. Browse to Research Papers Excel File.xlsx, pick Append a copy of the records to the table, choose Client, and click OK.

    Database Concepts

    Type a definition next to each term. No building.

    1. Open Database Concepts Master.accdb and open the Database Information table. The terms are already listed; you fill the Database Definition column.

    2. Type in the definitions. These are short versions to start from. Check them against your Ch. 10–11 notes, since grading may follow the notes' wording.

      Steps when creating a database
      Design first: decide what to store, lay out the tables, normalize, draw a relationship diagram. Then build it: create the structure, create relationships, enforce referential integrity, populate the data.
      Data
      Raw facts with no context or meaning on their own.
      Information
      Data that has been processed or organized so it's meaningful.
      Database
      Used to store information about a person, place, or thing; a collection of related tables.
      Table
      A collection of related records about one subject, organized in rows and columns.
      Record
      All the fields for one item or person; one row in a table.
      Fields
      A single piece of data about a record; one column in a table.
      Data type/Field type
      Defines what kind of data a field can hold (Short Text, Currency, Date/Time, Yes/No, etc.).
      Primary Key
      The field (or fields) that uniquely identifies each record in a table.
      Foreign key
      A field in a child table that matches the primary key of a parent table, used to relate the two.
      Requirements of a valid foreign key
      Same data type and size as the primary key it links to, and every value must match an existing primary key value in the parent table.
      Referential Data Integrity
      A rule that every child record must have a matching parent record, so there are no orphans.
      Cascade Updated records
      Changing a primary key in the parent automatically updates the matching foreign keys in child tables.
      Cascade delete records
      Deleting a parent record automatically deletes its related child records. It only works parent to child.
      Hierarchy of data in a database
      Database → Table (file) → Record → Field → Character (byte) → Bit.
      DBMS
      Database Management System: software used to create, manage, and query databases (e.g., MS Access).
      Structured Query Language
      The standard language used to query and manipulate relational databases.
      Data sheet View
      The view that shows a table's records in rows and columns, like a spreadsheet.
      QBE grid
      The Query By Example grid in query Design View, where you choose fields, criteria, and sorting.
      Dynaset
      The dynamic set of records a query returns; it reflects the current data in the tables.
      Report
      A formatted, printable presentation of data from tables or queries.

    3. Save and close.

    Same idea as Part 1, but you import from text files.

    Build the tables

    Keep the fields in exactly this order. The text files have no header row, so Access fills fields by position. Build everything and set up relationships before importing.

    1. Open CTC Consulting Master.accdb and create the Customer table.

    Relationships

    1. Close all tables, open Database Tools → Relationships, add all four tables, and make three links. Tick Enforce Referential Integrity (plus both cascade boxes, like Part 1) on each.

      Drag fromOnto
      Customer.CustomerIDClassEnrollment.CustomerID
      Class.ClassIDClassEnrollment.ClassID
      Instructor.InstructorIDClass.InstructorID

    Import the text files

    1. Go to External Data → New Data Source → From File → Text File.

    2. Browse to Customer.txt, choose Append a copy of the records to the table, pick Customer, click OK.

    3. Leave Delimited selected and click Next.

    4. Choose Comma, set Text Qualifier to ", leave First Row Contains Field Names unchecked, then click Finish.

    5. Repeat for the rest, in this order:

      OrderFileAppend toExpected rows
      1Customer.txtCustomer38
      2Instructor.txtInstructor5
      3Class.txtClass13
      4Class_Enrollment.txtClassEnrollment17

    6. Double-click each table to check the data landed, then close everything and save.

    7. Upload all three .accdb files to SimNet.

    If an import fails or skips rows, it's almost always a field name typo, fields in the wrong order, or importing a child table before its parent.
